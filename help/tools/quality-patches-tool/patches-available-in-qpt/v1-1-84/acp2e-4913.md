# ACP2E-4913：在数据库死锁后，不会重试REST API发运和发票创建

ACP2E-4913修补程序修复了在发生数据库死锁时，通过REST API创建装运或发票由于未重试操作而永久失败的问题。 安装[[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84时，此修补程序可用。 修补程序ID为ACP2E-4913。 请注意，此问题计划在Adobe Commerce 2.4.10中修复。

## 受影响的产品和版本

**为Adobe Commerce版本创建了修补程序：**

* Adobe Commerce（所有部署方法） 2.4.8-p3

**与Adobe Commerce版本兼容：**

* Adobe Commerce（所有部署方法） 2.4.7 - 2.4.8-p5

>[!NOTE]
>
>该修补程序可能适用于具有新[!DNL Quality Patches Tool]发行版本的其他版本。 要检查修补程序是否与您的Adobe Commerce版本兼容，请将`magento/quality-patches`包更新到最新版本，并在[[!DNL Quality Patches Tool]：搜索修补程序页面](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=zh-Hans)上检查兼容性。 使用修补程序ID作为搜索关键字来查找修补程序。

## 问题

如果由于未重试该操作而发生数据库死锁，则通过REST API创建装运或发票会永久失败。

<u>重现步骤</u>：

1. 准备多个可发运的订单和多个可开票的订单。
1. 由于集成可能正在加载中，因此请为这些订单并行发送多个`POST /rest/V1/order/<orderId>/ship`请求。
1. 以相同方式并行发送多个`POST /rest/V1/order/<orderId>/invoice`请求。
1. 检查API响应和`var/log/exception.log`。

<u>预期的结果</u>：

出现死锁后，将重试操作，并创建装运或发票。

<u>实际结果</u>：

某些请求失败，出现以下死锁错误。 未创建装运或发票，您必须人工创建它：

```
SQLSTATE[40001]: Serialization failure: 1213 Deadlock found when trying to get lock; try restarting transaction
```
