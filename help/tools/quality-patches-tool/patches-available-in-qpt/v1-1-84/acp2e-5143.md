# ACP2E-5143： GraphQL `route`查询呈现未请求的CMS页面内容

ACP2E-5143修补程序修复了以下问题：即使仅请求URL路由字段，GraphQL `route`查询也会呈现完整的CMS页面内容，包括页面生成器小部件和产品列表，这会减慢URL解析速度。 安装[[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84时，此修补程序可用。 修补程序ID为ACP2E-5143。 请注意，此问题计划在Adobe Commerce 2.4.10中修复。

## 受影响的产品和版本

**为Adobe Commerce版本创建了修补程序：**

* Adobe Commerce（所有部署方法） 2.4.7-p9

**与Adobe Commerce版本兼容：**

* Adobe Commerce（所有部署方法） 2.4.4 - 2.4.7-p10

>[!NOTE]
>
>该修补程序可能适用于具有新[!DNL Quality Patches Tool]发行版本的其他版本。 要检查修补程序是否与您的Adobe Commerce版本兼容，请将`magento/quality-patches`包更新到最新版本，并在[[!DNL Quality Patches Tool]：搜索修补程序页面](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=zh-Hans)上检查兼容性。 使用修补程序ID作为搜索关键字来查找修补程序。

## 问题

GraphQL `route`查询呈现完整的CMS页面内容的问题，包括页面生成器小工具和产品列表，即使仅请求URL路由字段也是如此，这会降低URL解析速度。

<u>先决条件</u>：

页面生成器已安装。

<u>重现步骤</u>：

1. 转到“管理员”>“**[!UICONTROL Content]**”>“**[!UICONTROL Elements]**”>“**[!UICONTROL Pages]**”，然后单击“**[!UICONTROL Add New Page]**”。
1. 输入页面详细信息，将&#x200B;**[!UICONTROL Enable Page]**&#x200B;设置为&#x200B;**[!UICONTROL Yes]**，然后单击&#x200B;**[!UICONTROL Content]**&#x200B;部分中的&#x200B;**[!UICONTROL Edit with Page Builder]**。 在页面生成器面板中展开&#x200B;**[!UICONTROL Add Content]**，然后将&#x200B;**[!UICONTROL Products]**&#x200B;占位符拖到舞台上，或将目录产品小组件插入到页面内容中。
1. 在“管理员”中，转到&#x200B;**[!UICONTROL Stores]** > **[!UICONTROL Settings]** > **[!UICONTROL Configuration]**。 在左侧面板中的&#x200B;**[!UICONTROL General]**&#x200B;下，选择&#x200B;**[!UICONTROL Web]**，然后展开&#x200B;**[!UICONTROL Default Pages]**。 将&#x200B;**[!UICONTROL CMS Home Page]**&#x200B;设置为新页面，然后单击&#x200B;**[!UICONTROL Save Config]**。
1. 发送以下GraphQL请求：

   ```
   query ResolveURL($url: String!) {
     route(url: $url) {
       relative_url
       redirect_code
       type
       ... on CmsPage { identifier __typename }
       ... on ProductInterface { uid __typename }
       ... on CategoryInterface { uid __typename }
       __typename
     }
   }
   ```

1. 为请求使用以下变量：

   ```
   { "url": "/" }
   ```

<u>预期的结果</u>：

`route`查询返回CMS主页的请求路由元数据和类型鉴别器字段，但不呈现其完整内容。

<u>实际结果</u>：

1. `route`查询呈现完整的CMS主页内容，即使仅请求路由元数据和类型鉴别器字段也是如此。
1. Page Builder小组件加载产品集合，从而增加响应时间和每个请求的数据库查询次数。
