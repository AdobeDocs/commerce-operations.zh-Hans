# ACP2E-5122：已处理的GraphQL购物车错误被错误地写入异常日志

ACP2E-5122修补程序修复了已处理的GraphQL购物车请求错误作为应用程序错误写入异常日志的问题。 安装[[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84时，此修补程序可用。 修补程序ID为ACP2E-5122。 请注意，此问题计划在Adobe Commerce 2.4.10中修复。

## 受影响的产品和版本

**为Adobe Commerce版本创建了修补程序：**

* Adobe Commerce（所有部署方法） 2.4.8-p5

**与Adobe Commerce版本兼容：**

* Adobe Commerce（所有部署方法） 2.4.4 - 2.4.9

>[!NOTE]
>
>该修补程序可能适用于具有新[!DNL Quality Patches Tool]发行版本的其他版本。 要检查修补程序是否与您的Adobe Commerce版本兼容，请将`magento/quality-patches`包更新到最新版本，并在[[!DNL Quality Patches Tool]：搜索修补程序页面](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html)上检查兼容性。 使用修补程序ID作为搜索关键字来查找修补程序。

## 问题

已处理的GraphQL购物车请求错误将作为应用程序错误写入异常日志。

<u>重现步骤</u>：

1. 发送包含无效、过期或已销毁的遮罩式购物车ID的GraphQL `placeOrder`变异，如以下变异：

   ```
       mutation {
           placeOrder(input: { cart_id: "test" }) {
               orderV2 {
                   id
                   number
               }
           }
       }
   ```

1. 检查GraphQL响应。
1. 检查`var/log/exception.log`购物车错误。

<u>预期的结果</u>：

1. GraphQL请求为无效的购物车返回经过处理的面向客户端的错误负载，且不带&#x200B;*HTTP 500*&#x200B;响应。
1. 处理的&#x200B;*GraphQlNoSuchEntityException*&#x200B;未写入`var/log/exception.log`，而是路由到较低严重性的日志通道。

<u>实际结果</u>：

每个请求都将已处理的异常以`report.ERROR`严重性写入`var/log/exception.log`，这会导致在重复请求期间出现无限制的日志增长。
