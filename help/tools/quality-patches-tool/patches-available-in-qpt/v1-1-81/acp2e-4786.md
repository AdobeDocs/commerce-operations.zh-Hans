# ACP2E-4786：配置AWS S3远程存储时，产品导出失败

ACP2E-4786修补程序修复了在启用AWS S3远程存储时，产品导出因存储驱动程序使用无效路径而失败的问题。 安装[[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.81时，此修补程序可用。 修补程序ID为ACP2E-4786。 请注意，此问题计划在Adobe Commerce 2.4.9中修复。

## 受影响的产品和版本

**为Adobe Commerce版本创建了修补程序：**

* Adobe Commerce（所有部署方法） 2.4.7-p4

**与Adobe Commerce版本兼容：**

* Adobe Commerce（所有部署方法） 2.4.5 - 2.4.9

>[!NOTE]
>
>该修补程序可能适用于具有新[!DNL Quality Patches Tool]发行版本的其他版本。 要检查修补程序是否与您的Adobe Commerce版本兼容，请将`magento/quality-patches`包更新到最新版本，并在[[!DNL Quality Patches Tool]：搜索修补程序页面](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html)上检查兼容性。 使用修补程序ID作为搜索关键字来查找修补程序。

## 问题

启用AWS S3远程存储时，由于存储驱动程序中的路径处理无效，产品导出失败。

<u>重现步骤</u>：

1. 将[!DNL AWS S3]配置为远程存储：

   ```
   bin/magento setup:config:set --remote-storage-driver="aws-s3" --remote-storage-bucket="..." --remote-storage-region="..." --remote-storage-key="..." --remote-storage-secret="..." -n
   ```

1. 通过运行以下命令禁用介质文件的数据库存储：

   ```
   bin/magento config:set system/media_storage_configuration/media_database 0
   ```

1. 在管理员侧边栏中，转到&#x200B;**[!UICONTROL System]** > **[!UICONTROL Data Transfer]** > **导出**。
1. 对于&#x200B;**[!UICONTROL Entity Type]**，请选择&#x200B;**[!UICONTROL Products]**。
1. 单击&#x200B;**[!UICONTROL Continue]**。

<u>预期的结果</u>：

已成功创建导出文件。

<u>实际结果</u>：

1. 未创建导出文件。
1. 日志显示&#x200B;*SignatureDoesNotMatch*&#x200B;错误。
